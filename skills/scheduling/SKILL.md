# 日程与提醒

## 默认值

- 时区:Asia/Shanghai(除非用户明说)
- 未指定时长的会议:默认 1 小时
- 未指定具体时刻的"上午/下午":上午 = 06:00–12:00,下午 = 12:00–18:00
- 未指定日期的时间词("周三"):先确认是本周还是下周,不要猜

## 提醒

- 用户说"提醒我"时,先确认**时间**与**事项**;缺一个就问。
- ⭐ **先分清是哪一种**(2026-10-13 用户拍板的口径):
  - **有产出、做完要勾掉的** → 记**待办**(todo_write,带 `due_at_local`),它自带到点提醒。
    例:"明天中午更新云朵智能体" → 待办「更新云朵智能体」,时刻 2026-10-14T12:00:00+08:00。
    **不要**只建一条提醒 —— 那样工作本身会丢,响过一次就什么都不剩。
  - **只是到点说一声、没有可勾的产出** → `schedule_create`(吃饭、喝水、站起来走走)。
  - **要占一段时间、要和别人对表** → 日程(calendar_schedule),它有自己的提前 N 分钟提醒。
- 重复提醒的最小间隔是 **300 秒**(代码强制),低于它会被直接拒绝。
- 提醒由**代码定时推送**,不依赖助手当时是否在对话、也不依赖模型是否"想起来"。
- 用户回一句"做完了"时:先 `todo_list` 找到那条待办,再 `todo_write(action="complete")`。

## 错题复习推送:不要用日程提醒代替

用户说"以后每天晚上七点半提醒孩子复习错题"时,**不要**去建一条每天重复的日程提醒 ——
那种提醒只知道"该复习了",不知道今天到底有几道题、是哪几道。

错题复习有自己的推送:用 `quiz_set_push` 设开关 / 时间 / 每日上限(也能指定学生)。
到点由**确定性调度器**生成当天真实的复习清单(几道、哪几科、卡在哪些知识点),
不经过模型、也不需要模型在线。用户也可以通过界面上的「推送设置」自己改。

## 冲突

- 新建日程与已有日程重叠时,先告知冲突,再问是否仍然创建。
- 改期要分清"只改这一次"和"此次及以后"。
