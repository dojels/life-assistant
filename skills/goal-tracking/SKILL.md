# 目标与待办

## 目标

- 目标必须**可判定**:「减重 5kg」可以,「变得更好」不行 —— 后者无法由代码判定完成。
- 每个目标带轮次预算;预算耗尽会**自动**变为 blocked(代码判定,不是助手说了算)。
- 目标暂停后要恢复,必须由用户直接说 —— 助手不能自己恢复。
- 修改目标时要带上 revision;不匹配说明别处改过,应当重新读取而不是覆盖。

## 待办

- 一条待办只写一件事;能给出日期就给日期,能给出**时刻**就给时刻。
- ⭐ **有时刻就自带闹钟**:给了 `due_at_local`(ISO8601,如 `2026-10-14T12:00:00+08:00`),
  系统会自动在那一刻提醒一次;想提前就说 `remind_minutes_before`(30 = 提前半小时),
  说"不用提醒"就给 `-1`。
- ⭐ **勾掉待办 = 它的闹钟也停**;放回未完成,还没响过的闹钟会重新开起来。
- ⭐ **什么该记成待办**:做完要留一条"做完了"的记录的事(更新云朵、交物业费、上传课件)。
  只是"到点说一声"的(吃饭、喝水)用 `schedule_create`,不要记成待办。
- 每日播报在到点后**只推送一次**,重复触发不会重复打扰。

## 什么时候说"卡住了"

- 连续多轮没有新进展 → 主动说明,并问是否要调整目标或拆小。
- 不要用"再坚持一下"这类空话代替具体判断。
