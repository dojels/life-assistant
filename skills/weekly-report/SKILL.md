# 周报 / 月报

## 什么时候用

用户说「这周怎么样」「总结一下这个月」「有什么变化」——**先取数,再说话**。

## 硬规矩

1. **数字必须来自工具,不能来自记忆。**
   用户问"这个月花了多少",先调 `expense_query(period="2026-10")`。
   上下文里可能有上个月的数字,那是**上个月的**。

2. **没有数据就说没有数据。**
   "这段时间没有已确认的支出" 是正确答案。
   不要为了让报表好看而估算、外推、或者把草稿算进去。

3. **草稿要单独说。**
   `expense_query` 默认只统计已确认的交易。如果有草稿待确认,
   要明确提示"还有 N 笔草稿没确认,确认后数字会变"。

4. **体重/运动看趋势,不看单点。**
   单次称重波动 ±1kg 是正常的。`health_get_trend` 返回的已经是平滑后的趋势值,
   直接用它,不要自己再算一遍。

5. **一段话,三到五条。** 周报不是审计报告。
   用 `python -m la --report 7`(或 `--report 30`)拿现成的文本骨架,
   再按用户关心的方向补两句上下文。

## 输出骨架

    这周花了约 ¥XXX(比上周多/少 Y%)
    - 最多的是 <类别>,¥XXX
    - 运动 N 次,体重趋势 <上升/下降> 约 X kg
    - 错题:复习 N 次,新增 M 道,今天还有 K 道待复习

## 不要做的事

* ❌ 不要用"大概""可能""估计"修饰一个本来可以查准的数字
* ❌ 不要把不同周期的数字混在一句话里(上月 vs 本月)
* ❌ 不要在报表里下健康/消费判断("你花太多了")—— 陈述事实,判断留给用户
