# 网页(html_page)

把一个网页做成**自包含的 HTML**:CSS/JS 全内联、不依赖任何外部资源,双击就能在浏览器里打开,
带 JS 交互(答题判分、折叠展开、滑块、计算器、纯前端图表)。

| 动作 | 用途 | 关键参数 |
| :--- | :--- | :--- |
| create(默认) | 写新页面 → 落产物区 + 登记 + 给预览/下载地址 | title、html |
| patch | 在**已生成的页面**上做精确片段替换(只动命中的那一处) | filename、old_string、new_string |
| source | 取回**当前**源码(改之前先取,不要凭印象) | filename |

**什么时候用**:用户明确要「网页 / 页面 / 在线小工具 / 能点的」。
**什么时候不用**:要 Word/Excel/清单/台账 → artifact_write;普通回答 → 直接在对话里说。
用户没要网页就别自己做一个出来。

## 写页面时必须知道的:预览是**沙箱化**的

生成物预览时被放进**不透明源的沙箱**(响应头 CSP sandbox + connect-src 'none'):
允许 JS 交互,但不给任何越界能力。所以:

| 不要用 | 原因 | 替代 |
| :--- | :--- | :--- |
| localStorage / sessionStorage / document.cookie | 不透明源下访问会**抛异常**,页面白屏 | 内存变量 |
| fetch / XMLHttpRequest / WebSocket | connect-src 'none',请求发不出去 | 数据写死在页面里 |
| 外部 CDN 的 css/js/字体/图片 | default-src 'none',一律不加载 | 内联;图片见下 |
| window.top / window.parent | 拿不到父页面 DOM | 不需要,只操作自己这一页 |

中文页面要带 `<meta charset="utf-8">`(漏了会乱码;只给片段时框架会自动补全文档头)。
手机优先:别把内容写死成宽屏,`<meta name="viewport">` 框架会补上。

## ⚠️ 先看这条:整份错题卷**别手写页面**

用户要「出一份错题卷 / 打印一份错题 / 出一份 HTML 试卷」时,用 **`quiz_make_sheet`**
(默认 `format=html`):它由服务端渲染,图形、照片、听力音频**都已经内联在里面**,
还会作为文件直接发给用户。你手写页面重排题目的话,几乎一定会漏掉图与声音
(实测:出来的卷子里一个 `<img>` 一个 `<audio>` 都没有,听力题只能写"让家长念" —— 见 D110)。
本技能是给"用户点名要一个**别的**网页"时用的。

## 图片:写路径就行,服务端负责内联

预览只放行 `data:` 图片,而**你拿不到图片字节** —— 所以内联由服务端做,
你只要写引用,写盘前它会换成 data: URI,页面因此真正自包含(下载到手机、断网也能看):

| 你写 | 结果 |
| :--- | :--- |
| `/assets/<素材id>`(⭐ **错题的照片与图形**,清单/卡片里给的 `photo_handles` `figure_handle`) | 内联 |
| `/materials/<素材编号>/file`(聊天里发来的图) | 内联 |
| `/artifacts/<产物id>`(之前生成过的图,以及 `audio_handle`) | 内联 |
| `data/media/materials/xxx.jpg`(相对项目根的路径) | 内联 |
| 只有文件名 `xxx.jpg` | 在素材区/产物区里按名字找,找到就内联 |
| `https://cdn.../x.jpg` | **不内联**,预览里也不显示(自检会提示) |
| 自己贴的 `data:image/...` 一大串 base64 | 别这么干(又贵又容易抄错);写路径 |

预算(超了保持原样并在结果里提示):单张 ≤1MB、一页 ≤8 张、合计 ≤4MB。手机原图常有 2~4MB,
超了就换小图(截图/缩略图)或者别放这张。

## 🔊 音频(听力题 / 听写):**先看有没有,再决定要不要做**

⭐ **第一件事:错题自带的音频已经在"录入那一刻"做好并绑在题上了**(见决策记录 D107)。
📷 同一条也适用于**图形与照片**:卡片/清单里的 `figure_handle` 与 `photo_handles`
就是可粘贴的 `/assets/<id>` 句柄(服务端会内联它们)。
⚠️ 页面上**不许**写"让家长念""打开错题页看图"来代替这两样 —— 那是把题弄丢了一半。
用 `quiz_me` / `quiz_list` 取题时,卡片里带 **`audio_handle`** 的就是它 ——
**直接用那个句柄 `/artifacts/<id>`**,不要再调 `tts_audio` 重做一遍:
重做会得到**另一段声音**(同一道题每次听都不一样),而且白花一次语音费与 token。

只有**没有** `audio_handle` 的(比如你临时想给页面加一段朗读)才走下面这条:

1. 调 **`tts_audio`** 生成音频 —— 它返回一段现成的 `<audio controls ...></audio>`
   和一个 `handle`(`/artifacts/<产物id>`)。听写节奏用 `mode=dictation`(词表用逗号/顿号分隔),
   正常朗读用 `mode=say`(默认);要英语发音就在 text 里写英文。
2. 把那段 `<audio>` **原样**粘进页面对应的位置,然后 create/patch 页面。保存时服务端会把音频
   内联成 `data:`。

| 你写 | 结果 |
| :--- | :--- |
| `<audio controls src="/artifacts/<产物id>"></audio>`(`audio_handle` 或 tts_audio 给你的那段) | ✅ 内联,能播 |
| `<audio src="单词.mp3"></audio>`(相对路径) | ❌ 内联不到 —— **页面是哑的** |
| `<audio src="data/media/.../x.mp3">`(指到产物/素材区的真文件) | ✅ 内联 |
| 用 `speechSynthesis` 念(JS 朗读) | ❌ 沙箱与微信 WebView 里都不可靠,别用 |
| 写"让家长念一下" | ⚠️ 只在**真的做不出音频**时才这样,并要说明原因 |

预算:单段 ≤2MB、一页 ≤6 段、合计 ≤8MB(与图片**分开算**)。超了会明确告诉你"这段会是哑的",
不会静默。

## 改需求:**先取源码,再最小改动**(必读)

用户说"标题改大点 / 右边溢出了 / 加一页 / 换个配色"时,**不要**照着自己的印象重写整页:

1. `html_page(action="source", filename=<那一页>)` —— 取回**当前**源码
   (源码里的 `ELIDED_BASE64_…` 是内联图片折叠后的记号:可以连它一起复制,别改它);
2. 只在源码里定位要改的那一段,`html_page(action="patch", filename=…, old_string=…, new_string=…)`;
   要改多处就多调几次 patch;
3. `old_string` 必须**逐字**来自第 1 步的源码,而且要能唯一命中(多带上下几行);
   命中 0 次或多次会被拒绝,拒绝文案里写了怎么办。

**为什么这么严**:同一处小改动,整页重做实测比最小 patch **贵 2.9 倍、慢 3.2 倍**,
而且重画时 class/CSS 会整体漂移 —— 用户看到的是"变了个风格"而不是"只改了那一处"。
本会话里对**同一标题**再 create 会被直接拒绝;只有用户明确说"整页重做/换个风格"才换新标题重画。

## 自检:结果里那几条提示要照做

落盘前会自检沙箱里做不到的事(外链 / localStorage / fetch / window.top),结果直接跟在工具返回里。
有提示就按提示改完再交付 —— 不改的话用户打开时那部分**不生效**。
没提示就是"页面自包含,自检通过"。
