## 几条贯穿全局的约定

**1. 事件日志是真源，页面是投影。**
每次写入都落一条事件（谁、何时、什么、能否撤销），页面与报表从事件重放。
所以"回执/撤销/使用报表/自我观察"用的是同一份数据，不会各算各的。

**2. 提示词由代码生成。**
`la/agent/prompts.py` 固定顺序：IDENTITY（边界，不可编辑）→ PERSONA（性情，可编辑）→
运行时上下文 → 记忆/证据 → 历史 → 当前这句。易变段放在**后面**，前面逐字节稳定，
这样前缀缓存才命中。

**3. 工具是唯一执行入口。**
主循环不直接调 handler。管线：schema 校验 → 阶段门禁（这一轮允许哪些工具）→ 风险门禁
（low 直通 / confirm 要批准 / never 拒绝）→ 执行（带超时）→ 头尾剪裁与脱敏 → 审计。
失败返回结构化错误码，不抛异常打断主循环。

**4. 写入必须可撤销。**
记账、日程、健康、错题、人格都走同一套 `ops_receipts`：写入成功留一条回执，界面上一点就退回。
模型"说了但没做"是明确的故障（有测试钉住：只有工具真返回成功才允许说"已记好"）。

**5. 记忆分三层。**
抽取（`memory/notes`）→ 裁决（`fact_adjudicator`，判"新增/修正/合并/待放行"）→ 用户确认
（`fact_gate`）。敏感事实默认掩码，不注入提示词；摘要池按预算检索，命中锚点回原文。

**6. 上下文有预算，压缩在回合结束后做。**
触发线写死 120k token，压到当前历史的 20%；轮内不压缩，避免打断任务。
每轮装配结果落 `data/trace/context.jsonl`，轨迹页逐字回放。

**7. SQLite 不糊弄。**
表用 STRICT；迁移按版本号顺序执行，升级不丢数据；没有 ORM，SQL 直接写在 storage/domain 里。

## 目录职责

| 目录 | 职责 |
|---|---|
| `la/config.py` | 全部常量与 `get_settings()`（环境变量只在这里读一次） |
| `la/base/` | 无业务依赖的基础件：时钟、解析、HTML/Excel/Word 生成、文件守卫 |
| `la/agent/` | 主循环、提示词、投影、压缩、轨迹、自我观察 |
| `la/tools/` | 工具定义与执行管线 |
| `la/domain/` | 业务域:每个域一个 service + schema + 路由 |
| `la/memory/` | 事实、摘要、检索、脱敏 |
| `la/web/` | FastAPI 路由、Jinja2 模板、静态资源 |
| `la/ops/` | 启动器、密钥、备份、回执、自检、版本 |
| `la/bridge/` | 微信适配器（可选） |
