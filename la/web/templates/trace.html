一次请求长什么样(工具 schema 到底在哪)

它和 messages 在同一次请求里,只是放在两个不同的字段中。 下面那本账数的只是 messages 那一格。 

POST {base_url}/chat/completions          ← 一次调用,不是两次
{
  "model": "{{ view.current.model }}",
  "messages": [ … 系统提示 / 记忆块 / 对话 … ],   ← 占用图左边那条;消息账数的是这里
  "tools":    [ … 每个工具的名字、说明、参数表 … ],  ← 同一份请求的另一个字段;每轮固定,压缩动不了
  "tool_choice": "auto",
  "stream": true
}
  • 模型两样都收得到 —— 所以它既知道"聊了什么",也知道"自己能做什么"。 工具清单之所以不写成 messages 里的一段文字,是因为官方接口要求它走 tools 这个 结构化字段:接口靠它把"模型想调哪个工具、参数是什么"变成机器可读的 tool_calls。
  • 钱照付,只是不记在 messages 那本账上 —— 它属于这一次请求的输入 token, 但每轮一模一样、删不得也压不动;并进 messages 的话,每一轮都会触发一次"该压缩了"(见 D95)。
  • 一轮里可能调用模型好几次 —— 模型要求调工具时,服务端执行完把结果作为 tool 消息追加进 messages,再发一次同样的请求(同样带完整工具清单), 直到它给出最终答复。
  • 只有到顶收尾那一轮例外 —— 工具额度用尽时把 tools 整个撤掉, 模型只能按已有结果成文(见 D101)。
